# 自动配置与解码

适用 Windows x64。把仓库交给 agent 后，让它先阅读根目录 `AGENTS.md`，即可按实际条件配置和处理用户指定的目录。首次配置需要联网下载免费运行库，之后音频处理在本机完成。

## 开始使用

```cmd
bootstrap-decoder.cmd
bootstrap-decoder.cmd --doctor
decode-music.cmd "D:\MusicDownloads" --output "D:\MusicDecoded" --report "D:\MusicReports\first.json"
```

也可以双击 `decode-music.cmd`，在提示后输入或拖入文件夹。缺少运行库时会自动配置。项目不包含歌曲，也不会自动扫描整块磁盘或写入现有正式曲库。

所有运行库放在仓库的 `.runtime`，逐曲材料默认保存在 `.cache/decoder-materials`。两者不上传。没有管理员权限安装步骤，不安装 Frida helper，不修改 Windows 安全设置或全局环境变量。

## 实际处理方式

| 输入 | 处理方式 | 前提 |
| --- | --- | --- |
| 普通 FLAC、MP3、OGG | 完整校验，按真实格式复制，字节保持一致 | 不需要 QQ |
| WAV、M4A、AAC 等可识别普通音频 | 交给 FFmpeg 完整校验后复制 | 以实际文件验收为准 |
| NCM | 本地读取容器，输出原音频编码 | 不需要 QQ；不把外部封面与标签重写进音频 |
| QMC static/map/RC4 | 按容器尾部或内嵌材料还原；MGG 也走此通用路线 | 不需要 QQ 进程；输出按真实文件头确定 |
| musicex v1 MFLAC/MGG | 文件标识 → 本机 QQ 缓存 ekey → 逐曲材料解析 → 静态解码；连续同标识 2/3 个 v1 尾部会先按结构剥离 | 当前用户、本机已有对应缓存材料 |
| KGM/KGMA/VPR v3 slot1 | 离线 v3 容器变换 | 独立合成全长音频通过；暂无该平台真实下载样本 |
| KGM/KGG crypto v5 | 明确等待 `kgm-v5-db-required` | 需要独立酷狗数据库路线，当前不支持 |
| KWM、Xiami XM、Ximalaya X2M/X3M、TM2/TM6 | 离线容器变换 | 独立合成全长音频通过；暂无该平台真实下载样本 |
| 未知封装或损坏文件 | 明确跳过、等待或失败 | 不伪造成功 |

扩展名仅作辅助。普通 FLAC 即使叫 `.mflac`，也按普通文件校验和复制。已加密的未知 `.flac` 不会因为后缀正确就被收集。上表区分真实歌曲、独立合成全长音频和仅有算法回归的证据；逐项状态见 [格式支持与验收状态](format-support.md)。

## QQ 的条件与限制

新入口不调用 qqd、Frida、QQ DLL 或客户端进程。缓存就绪时，不要求用户为脚本启动 QQ 或播放。它仍需要每首歌自己的材料，不能把 A 的密钥通用于 B。

已研究的客户端为 QQMusic 21.11 x86；缓存格式限定 MMKV v2–v4，musicex 输入限定 v1；提供器允许 256/512 字节材料；本机真实缓存样本均为 512，256 字节仅有合成测试，其他长度不猜测。MGG 与 MFLAC 共用逐曲材料边界，不能因为后缀是 `.mgg` 就跳过或猜密钥。其他客户端版本、机器硬件标识变化、复制自其他机器的缓存及未知封装不作兼容承诺。EncV2 的合成测试不等于真实 EncV2 歌曲验收。

如果报告显示 `local-material-missing`，先从桌面打开 QQ 音乐并登录，手动播放对应的已下载歌曲一次后重跑。新入口不会自行播放、附加进程或弹 Frida 安装许可；仍没有材料时保留等待结果。本轮未证明缓存缺失的全新歌曲可无条件离线处理。

## 缺少材料时手动准备

先运行脚本；已有材料时不必打开 QQ。只有报告显示 MFLAC/MGG 的 `waiting/local-material-missing`，才按下面步骤准备：

1. 从桌面正常打开 QQ 音乐并登录，不必为此以管理员身份启动。
2. 在 QQ 的“下载/本地歌曲”列表中，按报告中的歌曲名和原文件路径找到**对应的已下载原件**。界面名称可能随版本变化；不要只搜索后在线播放同名的其他版本，也不要靠给文件改后缀来导入。
3. 手动点击播放一次，确认能听到声音且进度在走。建议先保持 QQ 打开、登录，再返回脚本重试。此步骤可能让材料就绪，不能保证所有版本/文件都有效。
4. 用相同输入和输出目录重跑；已经成功的输出会重新验证并显示 `unchanged`。如果指定报告路径，要换一个新文件名，例如：

```cmd
decode-music.cmd "D:\MusicDownloads" --output "D:\MusicDecoded" --report "D:\MusicReports\retry-01.json"
```

仍然等待、或 QQ 提示“暂不支持该文件格式”时，保留原件和报告，检查是否选中了对应的下载原件及受支持客户端；不要反复重启、改后缀或安装 Frida。脚本不会自动接受许可、控制播放或退回附加进程。材料真正缓存后，以后的处理通常无需再次打开 QQ。

MGG 与 MFLAC 的 musicex 路线共用这套逐曲材料准备；材料就绪后走通用 QMC 分支，而不是按后缀跳过。MGG 是 QQ 下载可能产生的专属格式，与多种编码/音质分支有关，不能仅凭后缀判断音质；本机来源、样本歌曲和具体证据见 [MGG 来源与音质](mgg-origin.md)。

## 如何判断成功

`ok`、`unchanged` 是通过验证的结果。`waiting` 表示缺少前提，`failed` 表示验证失败，`skipped` 表示未处理。只要存在失败或等待，整个命令返回非零；只有跳过项也不能算成功。

FLAC 除完整 FFmpeg 解码，还核对 STREAMINFO 的完整 PCM MD5，防止半首歌被误判。只有具备完整 PCM 和最后音频帧 CRC 双重证据时，才移除解码候选中的非音频尾部。OGG 还验证全部页面的 CRC、序号、BOS/EOS 与完整封包；其他普通音频要求严格全长解码；复制前后哈希保持一致。每文件上限 256 MiB。

同内容输出再次运行显示 `unchanged`；不同内容的同名输出会被拒绝，不覆盖。源目录、输出和私有缓存必须分开。报告应保存到输入目录之外的新路径。

## 配置故障

首次下载失败可以重跑；已经校验通过的下载包会复用。校验不匹配会停止，不能关掉校验继续。`--doctor` 只检查已经配置的运行库。

已存在但不完整、或与新清单不一致的运行目录会保留并停止。使用新的仓库目录可重新配置，先保留旧现场。`LMT_ASSET_DIR` 或 `bootstrap-decoder.cmd --asset-dir "下载包目录"` 可复用离线准备的固定下载包，仍须通过同一 SHA-256 校验。

运行库清单：Python 3.12.10 便携版、Mutagen 1.47.0、PyCryptodomex 3.23.0、FFmpeg/ffprobe 9.0.2。下载来源及 SHA-256 固定在 `decoder-assets.json`。FFmpeg 为其官网链接的 Gyan Windows 构建；首次下载不表示获得了任何歌曲或账号权限。
