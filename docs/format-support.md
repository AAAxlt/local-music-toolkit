# 格式支持与验收状态

更新日期：2026-10-22。脚本覆盖常见音乐加密家族的已知变体；不以扩展名数量承诺“所有版本”或某个未经统计的覆盖比例。

| 格式／路线 | 当前支持与前提 | 验收证据 |
| --- | --- | --- |
| 普通 FLAC、MP3、OGG | 按内容识别、完整验证、原字节复制；不读 QQ 缓存 | 三种真实音频通过，源与输出 SHA-256 一致 |
| 普通 WAV、M4A/MP4、AAC、AIFF、APE、WMA | 已接入签名识别与 FFmpeg 验证 | WAV、MP4 有合成全长验收；其余未作真实文件承诺 |
| NCM | 文件内材料解密，保留原音频编码；不重写外部标签/封面 | 两首真实 NCM 完整解码，与仓库旧 Node 实现音频 SHA-256 一致，时长吻合 |
| QQ musicex v1 MGG | 需要对应文件自己的本机 QQ 缓存材料；通用 QMC RC4 路线 | 六首真实 MGG 完整解码为 OGG，含 O8M0/O4M0、1/2/3 个尾部标签；逐页 CRC、序号、BOS/EOS 及 FFmpeg 全长通过 |

| QMC static/map/RC4、raw ekey、QTag；QMC/Moo/微云等别名 | 无需进程；材料在文件中时直接处理。输出按真实内容定格式 | 上游固定版本黄金向量与 offset 边界通过；static/map/QTag 有独立合成全长音频验收；别名不等于每种平台下载均实测 |
| musicex 连续同标识尾部／较大尾部 | 仅有界剥离 span/version/identifier 一致的合法标签，不任意裁尾 | 双尾／三尾有真实 MGG；256 字节单尾仅合成测试 |
| KGM/KGMA/VPR crypto v3 slot 1 | 文件内材料，使用音频区相对偏移 | KGM、VPR 独立合成全长音频通过，并有独立字面量向量；暂无真实酷狗下载样本 |
| 酷我 KWM、虾米 XM、喜马拉雅 X2M/X3M | 本地文件变换；喜马拉雅内置算法表校验哈希 | 各路径独立合成全长音频及字节哈希通过；暂无这些平台真实下载样本 |
| QQ iOS TM2/TM6 | QQMU 头部还原；TM0/TM3 中的普通音频按内容复制 | TM2 合成全长音频通过；TM6 共用实现，暂无真实 iOS 下载样本 |
| KGM/KGG crypto v5 | **未支持**；返回 `waiting/kgm-v5-db-required`，不自动读取酷狗数据库 | 负例返回等待且无输出 |

| EncV2、其他客户端版本／机器 | 解析已有合成覆盖；不承诺未知版本 | 未验证真实 EncV2 歌曲或另一台干净 Windows |

## 本轮实际验收

- Windows：13 个真实输入全部成功（6 MGG、2 MFLAC、2 NCM、3 普通），用空的脚本材料缓存读取当前用户逐曲 QQ 缓存，总计 66.6 秒；所有研究副本和原件哈希未变。
- 依赖隔离：阻止 Frida 导入、QQ DLL 加载、进程读写和旧截取材料访问，触发次数为零；没有启动、关闭或控制 QQ 播放。
- 独立合成全长容器：10 个输入，输出字节与独立生成的预期一致；不允许读取 QQ 缓存。这些是合成音频，不能写成真实平台歌曲成功。
- 负例：截断 OGG、错误 CRC、缺材料、STag、KGM v5、同名不同内容输出，均按预期拒绝或等待，没有覆盖既有输出。
- Windows 回归：51 项全部通过，包括源变化不发布、逐曲材料隔离、MFLAC 门控、重复尾部、独立 KGM 向量。Linux 为 50 通过、1 项 Windows API 测试跳过。

## 使用边界与来源

musicex 文件仍需每首歌自己的材料；本地 QQ 缓存提供器允许 256/512 字节材料；本机真实缓存歌曲只验证了 512 字节，256 字节只有合成覆盖，其他长度不猜测。缓存缺失时按 [手动准备步骤](agent-decoder.md#缺少材料时手动准备) 打开 QQ、登录、播放对应下载原件后重试；不能保证任意新文件首次离线可解。

不依赖 Frida、qqd、QQ DLL、Go、REA 或 Bridge。自动配置清单不变；处理和验证在本机完成。源码包不包含歌曲、上游音频 fixture、真实逐曲材料、MMKV 或机器标识。干净验收仅是同一台 Windows 的新目录/新运行库模拟，不是另一台机器或新账号。
